One file lists every repo

Learn it · 6 of 6

Pick repos by label

--label web,docs

A comma list means any of them. Repeat the flag to require all of them.

--exclude-label legacy

Everything in scope except the repos with that label.

--label @workspace

A built-in label: only the nested workspaces.

Labels are free-form words stored on a repo in the manifest. The global --label and --exclude-label flags then narrow any multi-repo command: git, exec, run, worktree, repo list. Labels narrow the current scope and never widen it. Output is trimmed from a real run on the demo workspace. Full guide: docs/LABELS.md.

Extending meta

Add your own commands. Any language

Manifest plugin

Any executable plus a manifest file that declares its commands. Shell, Python or Go, with no protocol to learn.

Protocol plugin

A subprocess speaking JSON over stdio, with structured access to workspace state. A Rust SDK hides the protocol.

Module

A repo that bundles a plugin with the Claude skills that drive it, discovered when you add it as a project.

meta plugin install | list | verify | update | remove

Version pinning and optional checksums are built in. The rules and mcp features ship as external plugins in this very workspace.

Three plugin kinds exist: built-in (compiled in), protocol (subprocess, JSON over stdio) and manifest (executable plus manifest). Templates exist for Node, Python, Go and shell. A module is the distribution unit that bundles a plugin and skills. Sources: docs/PLUGIN_DEVELOPMENT.md and docs/MODULES.md.

Three questions, read left to right. One or two repos: plain git is enough. If you need atomic commits across projects, or build caching and affected-only tests, a monorepo with Nx, Turborepo or Bazel fits better. If the team never opens a terminal, a hosted platform fits better. Three yes answers: meta fits. The next two slides give the detail.

meta runs git and your commands across repos. It does not understand your build graph or merge changes atomically.

Say this plainly; it builds trust. meta is a coordination layer over independent repos, not a build system and not a monorepo substitute.
