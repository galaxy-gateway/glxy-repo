The idea

One file lists every repo

{
  "projects": {
    "api": "git@github.com:acme/api.git",
    "web": "git@github.com:acme/web.git",
    "docs": "git@github.com:acme/docs.git",
    "infra": "git@github.com:acme/infra.git",
    "sdk": "git@github.com:acme/sdk.git",
    "worker": "git@github.com:acme/worker.git"
  },
  "scripts": { "test": "npm test" }
}

The file is called .metarepo and sits at the top of the workspace. Think of it as a guest list.

acme/.metarepo

api

web

docs

infra

sdk

worker

Each repo keeps its own history, remotes and CI.

The repos line up under one manifest. It is plain JSON by default; YAML and TOML also work via meta init --format. Each entry maps a name to a git address. Scripts live in the same file. Older workspaces name the file .meta; both are discovered. Repo names and addresses on this slide are examples.
