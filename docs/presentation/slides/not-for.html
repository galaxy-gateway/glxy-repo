Honest limits

When not to use it.

SituationBetter fit
One or two reposPlain git
Atomic cross-repo refactorsA monorepo
Build graphs, caching, affected-only testsNx, Turborepo or Bazel
Coordinated package versioningChangesets or release tooling
Teams that never open a terminalA hosted platform UI

meta runs git and your commands across repos. It does not understand your build graph or merge changes atomically.

Say this plainly; it builds trust. meta is a coordination layer over independent repos, not a build system and not a monorepo substitute.
